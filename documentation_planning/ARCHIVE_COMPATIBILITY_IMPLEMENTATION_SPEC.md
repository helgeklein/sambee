# ZIP Compatibility Recovery Specification

## Purpose

Implement the remaining S4 and S5 compatibility work from
`ARCHIVE_SECURITY_MITIGATION_PLAN.md`.

The goal is practical interoperability: extract a ZIP member when its content
can be safely verified, and use a deterministic usable filename when a ZIP
producer supplied malformed UTF-8. The backend and Companion must make the
same decision for the same archive.

This is compatibility work. It does not add a new security subsystem, archive
repair mode, filename-encoding guesser, or recovery UI.

## Scope

This specification changes only ZIP-member streaming and ZIP filename decoding
in these paths:

- Backend: `backend/app/services/archive/zip_reader.py`.
- Companion: `companion/src-tauri/src/server/archive.rs`.
- Their focused parser and archive-operation tests.

It applies to direct ZIP inspection and extraction, and automatically applies
to both S1 relay directions because the executor holding the ZIP uses the same
reader.

## Policy

### Recoverable Compressed Payloads

The central directory defines each member's compressed-byte range. A Deflate
or BZIP2 decoder may finish before the end of that range. Bytes remaining in
the declared range are ignored when all of these conditions hold:

- the local header and declared byte range are valid;
- the decoder reaches a valid end of its first stream;
- the produced byte count equals the declared uncompressed size; and
- the produced CRC equals the declared CRC.

Those remaining bytes are not output, are not parsed as another ZIP record,
and are not concatenated as another compression stream.

The following continue to fail normally: unavailable codecs, unreadable or
out-of-bounds member ranges, truncated streams, output-size mismatch, CRC
mismatch, invalid local headers, unsafe paths, and unsupported archive member
types.

### Recoverable UTF-8 Names

When the ZIP UTF-8 flag is set but the name bytes are malformed, decode them
with deterministic U+FFFD replacement characters. Do not reject the member
solely for this condition and do not guess CP437 or another legacy encoding.

After decoding, apply the existing path normalization, safe-relative-path
checks, and collision policy. The raw central-directory filename remains the
value compared with the local-header filename; replacement affects only the
usable Unicode name.

Keep the current behavior for unflagged names: use a validated Info-ZIP Unicode
Path extra field when present, otherwise use the existing CP437 fallback.

## Implementation

### Backend

1. In `ZipReader.stream_validated_entry`, retain the existing compressed-size
   boundary, output-size accounting, CRC validation, and truncated-stream
   detection for Deflate and BZIP2.
2. Once a decoder reaches EOF, do not feed it further bytes from the declared
   member range. Treat those bytes as ignored trailing data. This is especially
   important for BZIP2, whose decoder may otherwise reject input after EOF.
3. In `_decode_name`, replace strict decoding for UTF-8-flagged names with
   `raw_name.decode("utf-8", errors="replace")`.
4. Do not alter local-header raw-name comparison or the existing path-safety
   checks.

### Companion

1. In `stream_validated_local_archive_entry_with_cancellation`, retain the
   `take(entry.compressed_size)` boundary and existing size and CRC checks.
2. Remove the post-EOF check that rejects leftover bytes from the bounded
   reader. The decoder must emit only its first stream; leftover bytes must not
   be included in output.
3. Keep `String::from_utf8_lossy` for UTF-8-flagged names. Do not add a strict
   invalid-UTF-8 error variant or a legacy-encoding fallback for flagged names.
4. Do not change normalized-path, file-type, or collision behavior.

## Tests

Add a small shared fixture description in `archive-contract/v2/fixtures/` and
exercise it from both backend and Companion tests. Fixture ZIP bytes may be
generated by the existing test helpers; the fixture description is the shared
expected-result contract.

Cover these cases:

| Case | Expected result |
| --- | --- |
| Valid Deflate and BZIP2 member | Extract declared verified content |
| Valid stream with trailing non-stream bytes in declared range | Extract declared verified content only |
| Valid first stream followed by a second stream in declared range | Extract first stream only when its declared size and CRC match |
| Truncated stream | Reject member |
| Wrong declared output size or CRC | Reject member |
| Valid UTF-8 flagged name | Preserve name |
| Malformed UTF-8 flagged name | Extract using the replacement-decoded safe name |
| Unflagged CP437 name | Preserve existing CP437 result |
| Replacement-decoded name collision | Follow existing collision policy without new implicit overwrite behavior |

For each accepted case, assert the output bytes and normalized output name. For
each rejected case, assert no successful member outcome. Run the same cases
through the backend reader and Companion reader. Add one direct extraction test
per runtime; S1 relay tests need only confirm that a backend-owned and a
Companion-owned source report the same result for one representative accepted
case and one representative rejected case.

Use at least one representative ZIP accepted by a common archive tool for each
recovery category. Keep it in the test data only when it demonstrates behavior
not already represented by a compact generated fixture.

## Non-Goals

- Do not attempt to infer the original encoding of malformed UTF-8-flagged
  names.
- Do not preserve malformed filename bytes as a user-visible archive identity.
- Do not concatenate compression streams or search beyond a declared member
  range.
- Do not alter destination collision policy, output naming policy, archive
  ordering, S1 source-session ownership, or relay authorization.
- Do not turn inspection into payload validation; listing remains metadata-only.

## Acceptance Criteria

- Backend and Companion extract identical bytes for all accepted fixtures.
- Backend and Companion produce the same normalized filename for every accepted
  filename fixture.
- Recoverable trailing compressed bytes and malformed UTF-8 alone do not reject
  an otherwise verified, safe member.
- Existing ZIP bounds, local-header, codec, path, file-type, size, and CRC
  checks retain their current rejection behavior.
- The focused backend ZIP-reader tests and Companion archive tests pass.
